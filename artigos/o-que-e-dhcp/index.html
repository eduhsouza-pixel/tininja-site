O que é DHCP e como funciona (DORA)

Conectou o computador e ele recebeu um IP sozinho? Entenda quem entregou essa configuração, o que acontece nas etapas DORA e por onde começar quando a distribuição falha.

O que é DHCP?

DHCP é o protocolo que entrega automaticamente a configuração de rede a um dispositivo. Em vez de preencher endereço IP, máscara, gateway e DNS em cada computador, você define a distribuição no servidor. O cliente solicita os dados e recebe uma concessão: a autorização para usar aquele endereço por um período.

Neste artigo, o foco é DHCP para IPv4. Pense no atendimento de um notebook novo: conectar o cabo não basta para preencher toda a configuração. Com o cliente em modo automático e um serviço DHCP acessível, essa etapa pode acontecer sem digitação. O servidor pode estar no roteador ou em outro equipamento da infraestrutura.

O protocolo organiza endereços; ele não comprova que a internet ou um sistema esteja funcionando. Receber um IP é uma etapa do diagnóstico, não o encerramento do chamado. A visão geral da Microsoft apresenta essa distribuição centralizada e as informações entregues ao cliente.

Como funciona o DORA

DORA ajuda a memorizar a troca inicial descrita na RFC 2131, seção 3.1. Imagine um computador entrando na rede sem uma concessão anterior:

Troca inicial de mensagens DHCP
EtapaMensagemO que acontece
DDiscoverO cliente procura servidores usando broadcast na rede local.
OOfferUm servidor oferece um endereço e parâmetros.
RRequestO cliente indica a oferta escolhida e solicita a configuração.
AACKO servidor confirma a concessão e seus parâmetros.

Pode existir mais de uma oferta. No processo inicial, o Request identifica o servidor escolhido, permitindo aos demais perceber que suas ofertas não foram aceitas. O ACK é a confirmação; receber apenas uma oferta não equivale a concluir a negociação.

E quando o computador já tinha IP?

Nem toda conversa repete as quatro etapas. Um cliente pode tentar reutilizar uma configuração conhecida ou renovar uma concessão. Por isso, ver um Request sem um Discover imediatamente antes não basta para concluir que a captura está errada.

Dica de bancada: antes de interpretar uma captura, anote se o computador acabou de entrar na rede ou já estava conectado. Esse contexto muda o que você espera encontrar.

IP, máscara, gateway e DNS: cada um tem seu papel

Use este exemplo didático, sem copiar os valores para uma rede real: computador 192.168.10.50, máscara 255.255.255.0, gateway 192.168.10.1 e DNS 192.168.10.2. Os endereços foram escolhidos apenas para explicar a configuração.

  • IP: identifica a interface naquela rede.
  • Máscara: delimita a sub-rede usada pelo computador.
  • Gateway padrão: indica o próximo salto para destinos sem uma rota mais específica.
  • DNS: indica o servidor consultado para resolver nomes.

Máscara, roteador e servidores DNS aparecem como opções na RFC 2132, seções 3.3, 3.5 e 3.8. Não confunda o servidor DHCP com o gateway: no exemplo, quem distribui a configuração pode ser outro equipamento. Também não trate DNS como sinônimo de acesso à internet.

Para praticar, coloque 192.168.10.50/24 na calculadora de sub-rede. Compare rede, broadcast e faixa de hosts com os endereços do exemplo. Depois altere o prefixo e observe por que olhar só os primeiros números do IP não é suficiente.

Concessão, escopo e reserva

A concessão tem prazo. O cliente tenta renová-la antes do vencimento; se ela expirar sem renovação, não pode continuar usando o endereço concedido. Isso permite reutilizar endereços sem tratar cada computador que passou pela rede como um cadastro permanente.

O escopo reúne a faixa de distribuição e suas configurações. Uma reserva associa um endereço a um cliente específico, mantendo a entrega pelo DHCP. Já a configuração manual é preenchida no próprio dispositivo. A documentação da Microsoft diferencia endereços disponíveis, excluídos e reservados.

Um exercício de planejamento

No laboratório do exemplo, anote primeiro o endereço do gateway e do DNS. Depois escolha quais endereços ficarão sob distribuição automática e quais precisarão de tratamento separado. Antes de aplicar, confira se algum dispositivo já usa o endereço escolhido. O objetivo é ter um registro que outro técnico consiga entender.

Cuidado: não configure um IP manual dentro de uma faixa distribuída automaticamente sem coordenar a exclusão ou o planejamento. Duas configurações independentes podem acabar usando o mesmo endereço.

Como começar o diagnóstico no Windows

Abra o Prompt de Comando ou o PowerShell e consulte a configuração completa:

ipconfig /all

Localize o adaptador realmente conectado. Registre IP, máscara, gateway, DNS e os dados de DHCP apresentados. Não misture a saída de Wi-Fi, Ethernet e interfaces virtuais. A documentação de ipconfig explica a consulta e a renovação.

  1. Confirme a conexão: confira cabo, Wi-Fi e a rede selecionada.
  2. Compare a configuração: o endereço pertence à sub-rede esperada? Existe gateway?
  3. Investigue a distribuição: confira se o serviço está disponível e se há endereços livres no escopo.
  4. Registre o resultado: salve o que mudou após cada teste, em vez de executar várias alterações juntas.

Um endereço de autoconfiguração 169.254.x.x pode indicar que o Windows não conseguiu obter uma concessão DHCP. A explicação da Microsoft sobre APIPA descreve esse comportamento. É uma pista para investigar a comunicação local, não prova de defeito no provedor.

Se a interface usa DHCP e você precisa tentar renovar, o comando é ipconfig /renew. Evite executar ipconfig /release durante um atendimento remoto: ele descarta a configuração atual e pode interromper a sessão. Primeiro entenda o efeito, depois decida se o teste é necessário.

Se o endereço está correto, avance para o serviço que falha. A seção de comandos dos vídeos ajuda a organizar os próximos testes. Não transforme toda falha de acesso em “problema de DHCP”.

Perguntas frequentes

O que significa DORA no DHCP?

DORA é a sequência Discover, Offer, Request e ACK da negociação inicial: o cliente procura um servidor, recebe uma oferta, solicita a configuração escolhida e recebe a confirmação.

DHCP e DNS são a mesma coisa?

Não. DHCP distribui a configuração de rede; DNS resolve nomes. O endereço do servidor DNS pode ser entregue ao cliente como uma opção DHCP.

Um IP 169.254 indica problema no provedor?

Não necessariamente. Um endereço de autoconfiguração 169.254.x.x pode indicar que o Windows não obteve uma concessão DHCP. Investigue a conexão local e o serviço DHCP antes de concluir que a falha é do provedor.
